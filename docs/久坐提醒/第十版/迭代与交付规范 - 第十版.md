# 迭代与交付规范-第十版

> **【归档基线】** 与实现版本 **v0.1.10** 对齐；归档日期：2026-05-14。

## 1. 迭代计划

### 1.1 版本迭代目标

交付第十版：**交互与隐私告知**、**解锁与久坐联动**、**调度快照**、**主窗高度 800**；保持第九版 **自动更新链路** 可用。

### 1.2 迭代里程碑节点

| 节点 | 产出 |
|------|------|
| M0 | 七份设计文档归档于 `docs/久坐提醒/第十版/` |
| M1 | 代码合并 `main`，版本号 **0.1.10** |
| M2 | 打标签 **`v0.1.10`**，`CHANGELOG` 含 **`## [0.1.10]`** |
| M3 | GitHub Release 构建成功，安装包与 **`.sig`** 上传 |

### 1.3 任务拆分与排期

- 前端：全屏、底部须知、HomePage 调度与监听、子页开关布局（**2～3 人日**）。
- 后端：快照命令、会话监听、Cargo 特性（**1～2 人日**）。
- 联调与测试（**1 人日**）。
- 文档与发版（**0.5 人日**）。

## 2. 代码管理规范

### 2.1 分支管理规则

- 第十版在 **`main`** 上迭代或以 **`feature/v0.1.10-*`** 短分支开发后 **squash/merge** 回 `main`（与仓库习惯一致即可）。

### 2.2 代码提交规范

- 提交信息须含 **功能点关键词**（如 `changelog`、`session_unlock`、`scheduler_snapshot`）。
- **禁止** 提交 `*.key`、本机私钥。

### 2.3 代码合并与评审规则

- 涉及 **Win 子类 + WTS** 的改动须 **Win 实机或 CI** 通过后再合并。

## 3. 构建与打包规范

### 3.1 构建环境要求

- Node **20**、Rust **stable**；与 **`.github/workflows/release.yml`** 一致。
- 环境变量 **`TAURI_SIGNING_PRIVATE_KEY`** 在 CI Secrets 配置齐全。

### 3.2 构建流程规则

1. `npm ci`
2. `npm run build`
3. `cargo build` / `tauri build`（以 workflow 为准）

### 3.3 打包产物规范

- Windows：**NSIS / MSI** + **updater `.sig`**（与第九版一致）。
- 版本号与 **`tauri.conf.json` / `Cargo.toml` / `package.json`** 一致为 **0.1.10**。

### 3.4 补丁/插件交付适配规则

第十版 **不引入** 新补丁包形态；插件沙箱规则不变。

## 4. 发布与部署规范

### 4.1 发布流程

1. 更新 **`CHANGELOG.md`** 增加 **`## [0.1.10]`**（**先于** 或 **同时于** 打标签，避免 CI 提取失败）。
2. 推送 `main`。
3. 创建并推送 **`v0.1.10`** 标签（指向含 CHANGELOG 的提交）。
4. 等待 **`release`** workflow 完成；检查 **Release** 资产与 **`latest.json`**。

### 4.2 部署环境要求

- GitHub **Releases** 可写；`contents: write` 权限已授予 workflow。

### 4.3 灰度发布规则

本应用 **无服务端灰度**；可选 **延迟公告** 或 **仅内测群** 先发安装包（运营策略，非强制技术门）。

## 5. 回滚规范

### 5.1 回滚触发条件

- **P0 缺陷** 在发布后 **24h** 内确认影响安全或数据。

### 5.2 回滚执行步骤

1. Git **revert** 问题提交或 **重置标签**（谨慎：已下载用户需说明）。
2. 重新跑 **release** 生成 **热修复小版本**（如 `0.1.11`）并更新 **latest.json**。

### 5.3 回滚验证标准

- 安装 **回滚后版本** 后：全屏右键、快照、解锁行为恢复 **预期基线**。

## 8. 线上运维规范

### 8.1 线上问题处理流程

- 用户报告「解锁无效」：先收集 **OS 版本**、是否 **Linux**、是否 **全屏中**、开关状态。
- 用户报告「重启后时间不对」：收集 **`scheduler_snapshot.json`** 是否存在、指纹是否变化。

### 8.2 日志与监控规范

- 客户端以 **用户可见 message** 与 **stderr（Rust setup）** 为主；**无** 集中式遥测。

### 8.3 迭代优化规则

第十一版若调整 **Darwin 通知名** 或 **快照 schema**，须 **递增 `schemaVersion`** 并保留迁移说明。
