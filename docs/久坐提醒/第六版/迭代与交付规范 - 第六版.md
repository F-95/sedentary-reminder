# 迭代与交付规范-第六版

> **【已锁定】** 锁定日期：2026-05-09。

## 1. 迭代计划

### 1.1 版本迭代目标

发布第六版：主题、规范 B、本地统计。

### 1.2 迭代里程碑节点

文档锁定 → 开发 → 联调 → 测试准出 → 打包。

### 1.3 任务拆分与排期

后端统计命令 → 前端主题与顶栏 → 简报与详情 → 测试与修复。

## 2. 代码管理规范

### 2.1 分支管理规则

建议分支名 `久坐提醒-第六版` 或与仓库约定一致。

### 2.2 代码提交规范

提交信息包含：第六版 + 模块 + 简述（如 `feat(v6): stats record command`）。

### 2.3 代码合并与评审规则

至少自测通过再合并；统计与主题变更需走 diff 评审。

## 3. 构建与打包规范

### 3.1 构建环境要求

Node 与 Rust 工具链与《文档元信息-第六版》一致。

### 3.2 构建流程规则

`npm ci` → `npm run build` → `cargo build` → `tauri build`。

### 3.3 打包产物规范

Windows NSIS/MSI；版本号与 `package.json` / `Cargo.toml` / `tauri.conf.json` 对齐（如应用发布 **0.1.6** 与 Git 标签 `v0.1.6`）。

### 3.4 补丁/插件交付适配规则

第六版不新增补丁包；核心命令变更需同步 capability 说明。

## 4. 发布与部署规范

### 4.1 发布流程

CHANGELOG、release notes、GitHub Release 附件安装包。

### 4.2 部署环境要求

用户本机安装；无服务端部署。

### 4.3 灰度发布规则

不适用；可提供预发布构建给内测。

## 5. 回滚规范

### 5.1 回滚触发条件

严重崩溃或数据损坏无法恢复。

### 5.2 回滚执行步骤

用户安装上一稳定版本；可选删除 `reminder_stats.jsonl` 重置统计。

### 5.3 回滚验证标准

提醒与第五版功能恢复；配置从 localStorage 仍可读。

## 6. 交付物清单

### 6.1 设计文档清单

本目录七份 Markdown（第六版）。

### 6.2 代码产物清单

`stats.rs`、前端新增/变更文件、`package.json` 依赖、`capabilities/default.json`、`tauri.conf.json` 默认窗高。

### 6.3 验收交付物清单

测试用例执行记录、构建日志、已知问题列表。

## 7. 验收标准

### 7.1 功能验收标准

与《需求规格说明书-第六版》P0 条目一致。

### 7.2 质量验收标准

无 P0/P1 未修复缺陷；自动化测试通过。

### 7.3 交付验收流程

测试签字（或等效确认）→ 发布。

## 8. 线上运维规范

### 8.1 线上问题处理流程

Issue 收集 → 复现 → 热修版本或下版合并。

### 8.2 日志与监控规范

本版无远程监控；可依赖用户反馈与本地文件。

### 8.3 迭代优化规则
