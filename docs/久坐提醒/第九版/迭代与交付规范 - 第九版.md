# 迭代与交付规范-第九版

> **【已锁定】** 锁定日期：2026-05-14。

## 1. 迭代计划

### 1.1 版本迭代目标

交付 **Windows 7/8/10 尽力兼容**、**底部版本与检查更新**、**Tauri Updater 签名更新** 的第九版可安装产物与配套文档。

### 1.2 迭代里程碑节点

- **M1**：配置与插件接入完成（本地 **cargo check / npm run check** 通过）。
- **M2**：UI 与更新联调通过（Win10）。
- **M3**：签名产物与 **latest.json** 在测试环境验证通过。

### 1.3 任务拆分与排期

由项目组按人天拆分：配置、前端、后端、测试、发布共五个工作包。

## 2. 代码管理规范

### 2.1 分支管理规则

分支名建议 **`久坐提醒-第九版`**（与仓库规范对齐）；合并前必须通过 **lint、typecheck、cargo check**。

### 2.2 代码提交规范

提交信息包含 **第九版** 关键字与变更点摘要（如 `第九版: 接入 updater 与底部版本栏`）。

### 2.3 代码合并与评审规则

至少一名熟悉 Tauri 的同事复核 **tauri.conf.json** 与 **capabilities** 变更。

## 3. 构建与打包规范

### 3.1 构建环境要求

- **Rust**、**Node** 版本与《文档元信息与全局开发共识-第九版》一致。
- 发布构建前在 shell 中导出 **TAURI_SIGNING_PRIVATE_KEY**（及密码变量）；**.env 不参与 Tauri 签名加载**。

### 3.2 构建流程规则

1. **node scripts/version.mjs** 设定目标版本（三处同步）。
2. **npm run build** 生成前端 **dist**。
3. **cargo tauri build** 生成 **NSIS/MSI** 及 **updater** 相关 **.sig**（**createUpdaterArtifacts: true**）。

### 3.3 打包产物规范

- **bundle/msi/**、**bundle/nsis/** 下安装包与 **同名 .sig** 成对出现。
- **latest.json** 中 **platforms.windows-x86_64**（及如需 **aarch64**）的 **url** 与 **signature** 与实际附件一致。

### 3.4 补丁/插件交付适配规则

第九版不改变补丁/插件打包规则；若更新后 API 有变须独立评估。

## 4. 发布与部署规范

### 4.1 发布流程

1. 在受控环境完成签名构建。
2. 将 **latest.json** 与安装包上传至 **HTTPS** 托管（默认示例为 **GitHub Releases**，路径见 **tauri.conf.json** 的 **endpoints**，发布前须替换为组织真实仓库或 CDN）。
3. 校验下载链接可匿名 **GET**（或按私有分发策略配置鉴权头，须同步改前端 **check** 配置）。

### 4.2 部署环境要求

- **TLS 有效证书**；**CORS** 非浏览器直连问题（由 Tauri 客户端请求）。

### 4.3 灰度发布规则

第九版不强制灰度；若需可在 **endpoints** 首条指向小流量静态 JSON。

## 5. 回滚规范

### 5.1 回滚触发条件

- 线上 **latest.json** 指向损坏包或签名错误导致大面积更新失败。

### 5.2 回滚执行步骤

- 将 **latest.json** 回退到上一稳定 **version** 与 **signature/url**；或临时返回 **204 无更新**（若使用动态服务端）。

### 5.3 回滚验证标准

- 客户端检查更新恢复为 **已最新** 或可安装上一稳定版本。
