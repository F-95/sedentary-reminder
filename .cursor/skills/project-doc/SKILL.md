# project-doc

## 核心定位

本技能用于标准化生成可直接用于AI编码的单一功能综合性设计文档，100%遵守《设计文档全局规则》与《设计文档固定大纲》，全程按固定文档顺序执行，逐文档唤醒对应负责角色的智能体，为每个文档生成**严格符合《设计文档固定大纲》**的独立设计文档，引导用户完成内容讨论、确认与锁定，最终按「docs/功能全称/版本号」目录结构归档全部文档，确保文档无歧义、可落地、无冗余，所有同类型文档大纲100%一致，完全适配单功能精细化迭代需求，全程禁止任何编程相关操作与内容输出。

## 触发场景

1.  新功能开发前，需要生成全流程、全角色对齐的7个独立设计文档
2.  现有功能迭代优化，需要生成新版本的设计文档，保留历史迭代记录
3.  标准化管控功能设计全流程，确保每个环节都经过用户确认，前后设计无冲突
4.  生成AI可直接编码落地的设计文档，避免AI开发时出现认知偏差、细节遗漏
5.  统一管理所有功能的设计文档，确保目录、命名、大纲结构完全符合规范

## 执行步骤（严格按顺序执行，无用户确认绝对禁止跳步）

1.  前置校验与任务初始化
    - 唤醒本技能后，第一时间向用户确认以下核心信息，未完整确认前，禁止进入后续流程：
      1.  本次设计的功能全称（精准唯一，用于一级目录命名，如「系统设置」「插件市场安装功能」）
      2.  本次任务类型：新功能开发 / 现有功能迭代
      3.  本次文档的版本号（如第一版、第二版，迭代版本必须比历史版本号递增，用于二级目录与文档命名）
      4.  功能的核心目标与一句话边界说明
    - 信息确认完成后，向用户明确告知完整的7个独立文档执行流程、对应负责角色、《设计文档固定大纲》中的固定大纲要求，再次确认是否开启本次文档生成任务
    - 校验当前会话是否仅处理本次单一功能，若会话中存在其他功能的上下文，必须提示用户开启全新会话执行本任务

2.  文档1：文档元信息与全局开发共识（负责角色：系统架构专家）

      1.  本次功能全称、版本号、核心目标与边界
      2.  项目固定技术栈：Tauri 2.0+、Rust、React 18+、Vite 5+、TypeScript
      3.  要求严格遵循《设计文档全局规则》，按照《设计文档固定大纲-文档1》中**固定章节大纲**输出完整内容，不得调整大纲顺序、删减必填章节
      4.  输出内容必须与项目已定义的目录结构规范100%对齐，明确代码存放路径、全局技术约束，**仅输出设计内容，禁止任何编程相关代码、命令输出**
    - 系统架构专家输出完成后，自动校验文档是否符合两大规则要求：①大纲是否完全匹配固定规范；②是否存在违规编程内容；③是否符合全局约束，不符合则重新生成；校验通过后，引导用户与专家进行内容讨论、修改、优化，直至用户明确输出「本文档确认无异议，可进入下一环节」的指令
    - 锁定本文档最终确认的内容，生成独立文档「文档元信息与全局开发共识-版本号.md」，同步到会话上下文，作为后续所有章节的全局约束，禁止后续环节违反本章定义的规则，禁止后续环节修改、覆盖本文档内容

      3.  在功能全称一级目录下，创建以「版本号」命名的二级子目录（已存在则直接使用，不覆盖）

## 强制输出规范

1.  必须输出7个独立的设计文档，每个文档严格对应固定名称与《设计文档固定大纲》中的固定章节大纲，禁止合并、拆分文档，禁止调整大纲结构
2.  所有文档内容必须100%符合《设计文档全局规则》与《设计文档固定大纲》的要求，覆盖所有必填的大纲章节，无缺项、无冗余
3.  所有内容必须以「AI可直接编码落地」为核心，只保留有明确约束、无歧义的确定性设计信息，**禁止输出任何代码片段、执行命令、编程相关内容**
4.  后续章节的内容必须严格基于前面已确认、已锁定的章节内容，禁止出现前后冲突、需求偏离的问题
5.  最终归档的文档必须格式规范、结构清晰、层级正确，无乱码、无格式错误，可直接归档使用
6.  文档的目录、命名必须100%符合「docs/功能全称/版本号」的规则要求，禁止出现任何格式偏差

## 绝对禁忌规则

1.  禁止在未完成当前文档用户确认、文档未锁定的情况下，跳步进入下一文档
2.  禁止在一个任务/一份文档中处理多个功能，禁止修改已确认、已锁定的前置文档内容
3.  禁止将7大核心章节合并到同一份文档中，禁止单章节内容拆分出多个独立文档
4.  禁止调整、修改、删减《设计文档固定大纲》中定义的固定章节大纲，禁止私自变更大纲顺序
5.  禁止未向用户展示完整的7个文档全文、合规性校验结果，就直接写入文件系统
6.  禁止覆盖、删除功能的历史版本目录与文档，禁止修改文档的存储路径与命名规则
7.  禁止输出与项目现有架构冲突、前后端设计不对齐、AI无法直接编码的模糊内容
8.  禁止在设计全流程中，以任何形式输出代码片段、执行命令、开展编程相关操作
9.  禁止违反《设计文档全局规则》与《设计文档固定大纲》中的任何约束要求
