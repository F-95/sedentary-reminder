## 1. 设计概述

### 1.1 设计目标

保持第二版及第一版后端命令集合与语义稳定；第三版「调度重算边界」「免打扰折叠 UI」及「跨午夜免打扰」均为前端职责，后端继续接收前端计算后的 next 镜像。

### 1.2 设计约束

- 第三版迭代范围内不新增、不修改 Tauri 命令签名。
- `ReminderRuntimeState` 不因第三版做结构性扩展。

### 1.3 参考依据（系统总体设计、需求规格说明书）

### 3.2 单个接口详细定义（表格化：请求路径、请求方法、请求参数、响应格式、错误码、权限要求）

#### update_next_trigger（第三版行为对齐说明）

| 项目 | 第三版说明 |
|------|------------|
| 调用名 | update_next_trigger |
| 请求参数 | `triggerAtMs`：可选 i64；`triggerLabel`：可选字符串 |
| 响应格式 | Result<(), String> |
| 语义 | 当前端因**非调度配置**变更而不重算 next 时，invoke 调用频次下降；镜像中已存在的 next 可保持不变；当前端因调度切片变更重算时，标签仍为前端格式化的本地时间字符串（含可能跨日展示）；后端不解析免打扰是否跨午夜 |
| 权限要求 | 同第二版 |

其余命令定义引用第二版/第一版表格，全文保持一致。

### 3.3 接口通用处理规则

后端不解析提醒配置 JSON；不感知「调度切片」概念。
