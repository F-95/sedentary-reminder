# 后端详细设计（Rust）-第八版

> **【已锁定】** 锁定日期：2026-05-12。

## 1. 设计概述

### 1.1 设计目标

第八版**不修改** Rust 命令签名与 `stats.rs` 读写策略：仍通过 `record_stat_event` 追加、`query_stat_events` 按闭区间返回；扩展 **`kind` 字符串约定** 以支撑前端枢纽与统计展示。

### 1.2 设计约束

- 不新增 `commands/*.rs` 文件；不修改 `generate_handler!` 注册表条目名称。
- 统计文件路径、保留期裁剪、整文件回写策略与第六版以来一致。

### 1.3 参考依据（系统总体设计、需求规格说明书）

《系统总体设计-第八版》《需求规格说明书-第八版》《后端详细设计（Rust）-第七版》《后端详细设计（Rust）-第六版》。

## 3. 接口详细设计

### 3.1 接口清单总览

与第七版相同：`record_stat_event`、`query_stat_events` 及第五版以来既有命令；**无新增命令**。

### 3.2 单个接口详细定义（表格化：请求路径、请求方法、请求参数、响应格式、错误码、权限要求）

#### record_stat_event（继承，第八版补充 kind 约定）

| 项目 | 说明 |
|------|------|
| 命令名 | `record_stat_event` |
| 请求方法 | Tauri command invoke |
| 请求参数 | `kind: String`（必填，第八版新增见下表）；`atMs: Option<i64>`（可选，缺省为服务端当前毫秒） |
| 响应格式 | `Result<(), String>` |
| 错误码 | 以 `Err(String)` 中文描述（文件 IO、序列化失败等） |
| 权限要求 | 与第六版以来该命令 capability 一致 |

**第八版新增 kind 约定（写入 JSONL，与前端一致）**

| kind 值 | 语义 | 写入方 |
|---------|------|--------|
| sedentary_activity_logged | 用户在枢纽点击「记录活动」 | 前端 |
| sedentary_skipped | 用户在枢纽点击「跳过本次」 | 前端 |

既有 kind：`sedentary_completed`、`sedentary_triggered`、`hydration_notified` 行为不变。

#### query_stat_events（继承）

| 项目 | 说明 |
|------|------|
| 命令名 | `query_stat_events` |
| 请求参数 | `fromMs: i64`、`toMs: i64`（闭区间） |
| 响应格式 | `Result<Vec<StatEventRecord>, String>`，元素字段驼峰序列化：`kind`、`atMs` |
| 权限要求 | 与第六版以来一致 |

### 3.3 接口通用处理规则

与第七版一致；`kind` 不做服务端枚举强校验（保持与历史版本兼容与扩展性）。

## 5. 核心业务逻辑设计

### 5.1 核心业务流程步骤

1. 前端 invoke `record_stat_event` 传入约定 `kind` 与可选时间戳。
2. `stats.rs` 读入、裁剪保留期、追加、排序、回写。
3. 前端 invoke `query_stat_events` 拉取时间窗内事件用于分桶与合计。

### 5.2 业务逻辑处理规则

后端不解析「活动次数合并」等业务语义；聚合规则仅存在于前端 `statsBuckets` 模块（见《前端详细设计（React）-第八版》）。

### 5.3 异常处理流程

与第六版一致；磁盘失败返回 `Err` 字符串。
