# 迭代与交付规范-第三版

> **【已锁定】** 锁定日期：2026-05-09。本文件为久坐提醒第三版基线文档，禁止直接修改；变更须于新版本目录全套归档。

## 1. 迭代计划

### 1.1 版本迭代目标

交付久坐提醒第三版：**调度重算依赖边界收紧**（非调度开关不刷新 next）、**免打扰时段折叠与摘要**、**跨午夜免打扰**；后端命令与持久化 v2 保持兼容。

### 1.2 迭代里程碑节点

| 里程碑 | 说明 |
|--------|------|
| M1 设计冻结 | 七份第三版文档归档 |
| M2 开发完成 | 前端实现与单元测试、Lint/构建通过 |
| M3 回归完成 | 第二版核心用例 + 第三版增量用例通过 |
| M4 发布候选 | 打包 RC，Release Note 说明行为变更 |

### 1.3 任务拆分与排期

以前端为主；后端冒烟验证命令无签名变更；测试维护增量用例表。

## 2. 代码管理规范

### 2.1 分支管理规则

建议使用分支名：`久坐提醒-第三版`；合并前 Pull Request 评审。

### 2.2 代码提交规范

提交信息包含：`久坐提醒-第三版`、变更关键词、对应设计章节（如「需求 US3-P0」「前端 §6 交互流程」）。

### 2.3 代码合并与评审规则

至少一名评审；调度依赖变更须附自测记录或测试结果摘要。

## 3. 构建与打包规范

### 3.1 构建环境要求

与第二版锁定版本一致。

### 3.2 构建流程规则

版本号升级须保持 `package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json` 与应用信息返回版本一致（延续第二版检查项）。

### 3.3 打包产物规范

Release Note 明确：「下次提醒时间」在非调度开关下保持不变；免打扰页支持折叠；支持跨午夜时段（结束早于开始表示至次日）及推迟规则说明。

### 3.4 补丁/插件交付适配规则

第三版能力属核心前端行为，默认不以插件交付；若补丁化须单独评审。

## 4. 发布与部署规范

### 4.1 发布流程

标签驱动 CI → Draft Release → 验证行为说明 → Publish。

### 4.2 部署环境要求

与第二版一致。

### 4.3 灰度发布规则

可先内测收集「next 是否仍跳动」与「跨午夜段是否按预期推迟」的反馈。

## 5. 回滚规范

### 5.1 回滚触发条件

第三版出现 next 不同步、提醒文案陈旧等严重缺陷。

### 5.2 回滚执行步骤

代码回退至第二版稳定标签构建；用户侧 v2 配置通常可共用，无需强制清理。

### 5.3 回滚验证标准

第二版 P0 用例全通过；用户可继续使用 v2 存储键。

## 6. 交付物清单

### 6.1 设计文档清单

第三版全部七份文档 + 第二版及第一版历史文档（追溯）。

### 6.2 代码产物清单

变更的前端源码、类型声明；无后端签名变更时仍记录验证结论。

### 6.3 验收交付物清单

测试记录（含 TC3 与第二版回归抽样）、Release Note、已知问题列表。

## 7. 验收标准

### 7.1 功能验收标准

满足《需求规格说明书-第三版》量化验收条目。

### 7.2 质量验收标准

P0 缺陷清零；构建与类型检查通过；Lint 零告警（以仓库规则为准）。

### 7.3 交付验收流程

测试报告 → 产品确认 → 架构确认文档与实现一致。

## 8. 线上运维规范

### 8.1 线上问题处理流程

区分「next 误刷新」与「折叠 UI」类标签；收集复现步骤与配置是否仅含非调度变更。

### 8.2 日志与监控规范

与第二版一致；可选本地日志，不上传远端。

### 8.3 迭代优化规则

跨午夜、按周免打扰等仍进后续版本需求池。
