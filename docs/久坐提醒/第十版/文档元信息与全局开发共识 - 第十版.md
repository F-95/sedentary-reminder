## 2. 全局技术栈规范

### 2.1 固定技术栈与版本号约束

在第九版基线之上保持不变，增量约束如下：

- Tauri `2.x`（以仓库 `Cargo.lock` 解析为准）、Rust Edition `2021`
- React `18.x`、Vite `5.x`、TypeScript `5.x`、Ant Design `5.x`
- 前端 `@tauri-apps/api`、`@tauri-apps/plugin-notification` 等与第九版一致
- **Windows**：`windows` crate 启用 **`Win32_System_RemoteDesktop`**（`WTSRegisterSessionNotification` 等）
- **macOS**：`core-foundation-sys`（Darwin 通知中心订阅锁屏解锁相关通知名）

### 2.2 依赖版本管理规范

- 语义化版本仍通过 **`node scripts/version.mjs <semver>`** 同步 `package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json`。
- 调度快照与统计文件均位于 **应用数据目录**；**不得**将用户提醒配置、统计事件、调度快照上传至业务方自有服务器（与本版「用户须知」承诺一致）。

### 2.3 跨平台兼容要求

- **Windows 10+ x64**：会话解锁监听以 **主窗口 HWND** 注册 **WTS** 通知 + **独立子类 ID** 消费 `WM_WTSSESSION_CHANGE`，与既有企业强控子类 **隔离**。
- **macOS**：以 **Darwin Notify Center** 订阅 **`com.apple.screenIsUnlocked`**（系统约定名；若未来系统变更通知名，须在新版本设计文档中单独评估）。
- **Linux 及其他**：本版 **不实现** 会话解锁 emit；前端开关存在但无后端事件属预期行为，须在《测试与验收方案》中列为 **平台能力差异**。

## 3. 全局代码规范

### 3.1 目录结构规范

第十版增量（相对第九版）：

- `src-tauri/src/commands/scheduler_snapshot.rs`：调度快照读写命令
- `src-tauri/src/platform/session_unlock.rs`：跨平台会话解锁监听与 **`session-unlocked`** 事件 emit（`cfg` 分平台实现）
- `src-tauri/src/platform/mod.rs`：导出 `session_unlock`（受 `cfg` 约束）
- `src-tauri/src/commands/mod.rs`：注册 `scheduler_snapshot` 模块
- `src-tauri/src/main.rs`：`setup` 中安装会话监听；`invoke_handler` 注册快照命令
- 前端：`HomePage.tsx`、`ReminderFullscreenPage.tsx`、`SedentaryReminderSettingsPage.tsx`、`quietHours.ts`、`tauri.ts`、`global.d.ts` 等增量

### 3.2 命名规则约束

- 配置字段 **`logActivityOnSessionUnlockEnabled`**：camelCase，与 `ReminderConfig` 及 Rust serde **camelCase** 镜像一致。
- Tauri 事件名 **`session-unlocked`**：全小写 + 短横线风格，与前端 `listen` 常量一致。
- 快照文件名 **`scheduler_snapshot.json`**：全小写 + 下划线，与统计 **`reminder_stats.jsonl`** 区分职责。

### 3.3 代码编写通用规范

- 全屏层禁止依赖「覆盖 AntD 全局样式」实现右键屏蔽；应使用 **DOM 事件层**（`contextmenu` + 捕获）与 **`preventDefault`**。
- 用户须知文案须 **可核验**（与真实落盘位置一致），避免夸大「绝对安全」类不可证表述。
- 调度指纹 **`buildSchedulerFingerprint`** 仅包含影响 **`computeNextTriggerWithQuietHours`** / **`computeNextIntervalFireWithQuietHours`** 的字段切片，**不得**掺入与排程无关的 UI 偏好字段，避免误拒快照。

## 4. 全局权限与安全规范

### 4.1 接口权限通用规则

- 新增命令 **`load_scheduler_snapshot`**、**`save_scheduler_snapshot`** 归入既有 **default** capability（与 `record_stat_event` 同级文件 IO 模式）；**不得**单独开放任意路径读写。
- **`session-unlocked`** 为后端 **emit → 前端 listen**，不新增前端可调用的危险 IPC。

### 4.2 数据安全规范

- 快照文件含 **下一拍绝对时间** 与 **配置指纹**；不包含用户身份、不包含聊天内容；丢失与损坏时回退为 **按当前时刻重算**，不得静默联网恢复。
- **解锁视为记录活动** 仅影响 **久坐调度与统计**，**不得**在补水全屏（本应用无补水全屏）或无关模块中副作用写 `update_next_trigger`。

### 4.3 合规性要求

- 用户须知须声明：**提醒配置（localStorage v2）、统计（JSONL）、调度快照（JSON）均仅存本机**；**不上传云端** 指本应用默认不实现上报通道（与第九版 Updater 拉取安装包行为区分：安装包来源为 HTTPS 静态资源，非用户行为数据上传）。

## 5. 需求优先级定义

### 5.1 P0 核心需求清单

- 全屏久坐提醒界面 **无系统默认右键菜单**（返回/刷新等）。
- **调度快照**：进程重启或就地升级后，在 **指纹一致且下一拍仍晚于当前时刻（含 2s 松弛）** 时延续久坐/补水下一拍；否则重算。
- **会话解锁**：在 Windows/macOS 上 **可靠 emit** `session-unlocked`；前端在开关开启且非全屏提醒态下执行与「记录活动」等价的调度推进。

### 5.2 P1 重要需求清单

- 主界面底部 **用户须知**（含 Tooltip 详述）。
- 久坐子页 **解锁视为记录活动** 与标题 **同一行** 展示开关。
- 主窗默认高度 **800px** 与提醒结束恢复尺寸一致。

### 5.3 P2 次要需求清单

- Linux 会话解锁 **留空实现** 的文档化与测试标注。
- 快照与统计文件 **手动删除** 后的降级体验说明（归入《迭代与交付规范》运维小节）。
