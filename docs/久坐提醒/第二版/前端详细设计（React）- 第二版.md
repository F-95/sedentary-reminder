# 前端详细设计（React）-第二版

## 1. 设计概述

### 1.1 设计目标

扩展提醒配置模型与设置界面，引入免打扰时段列表与推迟调度算法；保证旧配置迁移与回归兼容。

### 1.2 设计约束

- 不改变 Ant Design 全局主题配置位置。
- 页面级组件继续使用 AntD 原生组件组合。
- 推迟算法实现为可测试的纯函数模块（建议新建 `src/utils/` 下专用文件承载逻辑与类型导入）。

### 1.3 参考依据（系统总体设计、需求规格说明书、后端详细设计）

《系统总体设计-第二版》《需求规格说明书-第二版》《后端详细设计（Rust）-第二版》《前端详细设计（React）-第一版》。

## 2. 前端目录结构定义

### 2.1 目录层级规范

新增建议文件（名称小驼峰）：`quietHours.ts`（或等价命名）用于：

- 常量（最大段数、最大推迟迭代次数）
- 类型导出（若不放全局 d.ts）
- 纯函数：`migrateV1ToV2`、`computeNextTriggerMs`（名称可调整）

### 2.2 各目录职责定义

| 路径 | 第二版职责 |
|------|------------|
| pages/HomePage.tsx | 接入推迟函数；在调度 effect 中调用；维护本地视图状态（如 `main` \| `quiet`）在「主设置」与「免打扰设置」之间切换，**不引入路由库** |
| pages/ReminderSettingsPage.tsx | 仅承载与第一版一致的主设置区（开机自启、启用提醒、锁屏开关、提醒间隔、活动倒计时、提醒文案）；可选 prop（如 `onOpenQuietHours`）提供进入免打扰页的入口 |
| pages/QuietHoursSettingsPage.tsx | 免打扰专页：总开关、说明文案、时段列表 CRUD、段级启用、新增上限提示、返回主界面 |
| utils/tauri.ts | 不变（无新命令） |
| types/global.d.ts | 扩展 `ReminderConfig` 与 `QuietHourRange` |

### 2.3 文件命名规则

与项目规范一致。

## 3. 页面路由设计

### 3.1 路由清单总览

与第一版一致（无路由库、无 `react-router`）；设置相关界面通过 `HomePage` 内本地状态切换视图，不产生浏览器式路由历史。

### 3.2 路由权限定义

不适用。

### 3.3 路由跳转规则

不适用；**视图切换规则**如下（等价于应用内「子页」）：

- 默认展示主设置视图（`ReminderSettingsPage`）。
- 用户点击主设置页底部「免打扰时段设置」→ 切换至免打扰视图（`QuietHoursSettingsPage`）；`ReminderConfig` 仍由 `HomePage` 持有，切换不丢状态。
- 用户在免打扰页点击「返回主界面」→ 切回主设置视图；已修改项已通过同一 `onChange` 写回并随 `persistReminderConfigV2` 持久化（与编辑时机一致）。

## 4. 组件设计

### 4.1 组件拆分规则

免打扰列表固定在 `QuietHoursSettingsPage` 页面内实现；若未来复用需求出现，可再提取至 `src/components/` 下的业务命名组件（示例：`QuietHourRangesEditor.tsx`，遵循大驼峰）。

### 4.2 通用组件定义

可选提取「单行时段编辑器」以减少重复（当前落地为页面内联实现）。

### 4.3 页面组件定义

| 组件 | 第二版增量 |
|------|------------|
| ReminderSettingsPage | 保持第一版字段集；新增可选回调 `onOpenQuietHours` 渲染「免打扰时段设置」入口（仅主界面需要时传入） |
| QuietHoursSettingsPage | 免打扰总开关 + 时段列表 + 新增/删除 + 段级开关 + 返回主界面；时段起止使用 AntD `InputNumber`（时、分）**同一行横向排列**，控件宽度紧凑以避免在窄窗口下撑破布局 |
| HomePage | 使用新算法生成 `nextTriggerAt`；按视图渲染上述两页之一 |

### 4.4 组件Props/State类型定义

- `ReminderConfig` 扩展字段参见总体设计文档。
- `QuietHourRange`：`id`、`enabled`、`startMinutes`、`endMinutes`。

## 5. 接口请求设计

### 5.1 请求封装规范

保持集中封装；无新增 invoke。

### 5.2 与后端1:1对齐的接口请求定义

继续仅调用第一版已有命令；`updateNextTrigger` 传入的最终时间为推迟后的结果。

### 5.3 请求/响应拦截规则

不变。

### 5.4 异常处理规范

迁移失败 → `message.error` 提示并使用安全默认配置。

## 6. 交互流程设计

### 6.1 页面核心交互流程

用户从主界面进入免打扰页 → 编辑免打扰（总开关或各段）→ 校验与即时写回 `config` → `persistReminderConfigV2` → HomePage 调度 effect 依赖 `config` 重新计算 next → 调用 `updateNextTrigger`。返回主界面不改变上述数据链，仅切换视图。

### 6.2 加载状态处理

启动读取：优先尝试 v2；不存在则读取 v1 并迁移写入 v2。

### 6.3 异常状态处理

- 推迟迭代超过阈值：弹出告警并使用兜底候选（文档化策略：保持当前候选立即触发或固定在阈值时刻——实施时必须在注释中写死选择；推荐：**保持最后一次移位后的时间不再移位**并告警）。

### 6.4 空状态处理

列表为空且总开关开启：等价于无禁区。

## 7. 全局状态管理设计

### 7.1 状态管理方案

保持 React 本地状态。

### 7.2 全局状态定义

`ReminderConfig` 扩展字段纳入单一状态树。

### 7.3 状态更新规则

更新列表时使用不可变拷贝；删除行需确认可选（产品可选）。

## 8. 通用规范设计

### 8.1 样式设计规范

主设置与免打扰分属两视图；免打扰页内分组使用 `Typography.Title` / `Card` 等 AntD 结构，避免自定义全局样式穿透。主设置页文案区与入口链接纵向间距保持紧凑，以降低主窗口出现滚动条的概率。

### 8.2 性能优化规范

推迟算法 O(迭代次数 × 段数)，段数上限 20，可接受。

### 8.3 兼容性适配规范

时间换算一律基于本地时区 `Date` API。

## 附录 A：持久化与迁移（规范性说明）

| 键名 | 用途 |
|------|------|
| reminder-config-v1 | 历史版本只读迁移源 |
| reminder-config-v2 | 第二版起正式读写键 |

迁移策略：

1. 若仅存在 v1：解析为第一版结构 → 附加默认 `quietHoursEnabled=false` 与空 `quietHours` → 写入 v2。
2. 若已存在 v2：忽略 v1。
3. 写入失败：提示用户并不触发静默数据丢失（降级为内存默认）。

## 附录 B：推迟算法（确定性文字流程）

输入：`baseNowMs`（调度基准时刻）、启用规则集合、`quietHoursEnabled`、`quietHours`。

步骤：

1. 若提醒总开关关闭或 `quietHoursEnabled=false`：按第一版规则，对每个已启用规则计算「基准毫秒时间戳加上间隔分钟换算后的毫秒增量」得到候选时间集合，取其中的最小值作为 `next`（与当前 `HomePage` 一致）。
2. 否则先执行与步骤 1 相同的计算得到第一版候选 `t0`。
3. 将 `t0` 映射到本地日历的「分钟内索引」`m0`。
4. 收集所有 `enabled=true` 的区间 `[s,e)`（左闭右开）满足 `s < e`。
5. 若 `m0` 不在任何区间内：`next = t0`。
6. 否则令 `Emax` 为所有覆盖 `m0` 的区间最大 `e`（分钟索引）；将基准日期对应的毫秒时间拨到 `Emax` 分钟处，再加上 `intervalMinutes` 得到新候选 `t1`。
7. 重复步骤 3–6 使用 `t1`，迭代计数 +1，直到不命中或达到上限。
8. 达到上限：调用告警策略并返回最后一次候选。

说明：采用左闭右开区间避免相邻时段边界双命中歧义；具体边界是否包含端点须在开发注释中与产品图示对齐。

## 附录 C：与提醒会话的中断策略

当 `reminderVisible=true` 或存在活动会话时：第一版已有逻辑暂停调度；第二版保持该行为，不在会话中途重算 next。
