# 测试与验收方案-第九版

> **【已锁定】** 锁定日期：2026-05-14。

## 1. 测试概述

### 1.1 测试范围

第九版增量：**Windows 安装与首次启动**、**WebView2 引导**、**主界面底部版本展示**、**检查更新全流程**、**版本号一致性**、**capabilities 权限**、**回归第八版 P0 枢纽与统计**。

### 1.2 测试目标

证明在目标 Windows 环境下应用可安装、可启动、可更新、版本展示正确，且第八版核心功能无回归。

### 1.3 参考依据

《需求规格说明书-第九版》《系统总体设计-第九版》《前端详细设计（React）-第九版》《后端详细设计（Rust）-第九版》。

## 2. 测试环境与工具

### 2.1 测试环境配置要求

| 环境 | 最低要求 |
|------|----------|
| Win10 x64 虚拟机 | 22H2 或企业常用稳定版；可联网 HTTPS |
| Win8.1 x64 虚拟机 | 已打重要更新；可联网 |
| Win7 SP1 x64 虚拟机（扩展） | 已安装兼容 **WebView2 固定版**（版本号记录在测试记录表） |
| 构建机 | 安装 **Rust stable**、**Node LTS**；配置 **TAURI_SIGNING_PRIVATE_KEY** 用于生成带 **.sig** 的发布物 |

### 2.2 测试工具清单

- 应用自带 UI；可选 **Fiddler** 或系统代理观察 HTTPS 请求（更新检查）。
- **事件查看器**（Windows）辅助查看安装失败原因。

### 2.3 测试数据准备规范

- 准备两份 **latest.json**：版本 **低于当前**（预期无更新提示）；版本 **高于当前** 且 **signature/url** 与 **.sig** 及安装包匹配（预期走完整更新）。
- 记录每轮测试的 **WebView2 Runtime** 版本（`edge://version` 或系统组件信息）。

## 3. 分级测试用例设计

### 3.1 P0核心用例（核心功能场景）

| 编号 | 前置条件 | 步骤 | 预期结果 |
|------|----------|------|----------|
| T9-P0-01 | 已安装当前构建 | 打开主窗口，切换至任意子页 | 底部始终显示 **v{与 tauri.conf 一致}** |
| T9-P0-02 | 同左 | 点击刷新图标 | **60s 内**完成检查或错误提示；过程中按钮防重复有效 |
| T9-P0-03 | 更新源返回无更高版本 | 点击刷新 | 提示 **当前已是最新版本** |
| T9-P0-04 | 更新源返回更高版本且签名正确 | 点击刷新 → 确认安装 | 下载安装执行；应用 **重启** 后版本号升高 |
| T9-P0-05 | 同左 | 点击刷新 → 取消 | 不安装；应用不崩溃；可再次检查 |

### 3.2 P1重要用例（重要功能、边界场景）

| 编号 | 前置条件 | 步骤 | 预期结果 |
|------|----------|------|----------|
| T9-P1-01 | 干净 Win10 无 WebView2 | 运行安装包 | 引导安装或下载 WebView2 后应用可启动主界面 |
| T9-P1-02 | 执行 **version.mjs**  bump | 读三处文件与 **get_app_info** | 版本号完全一致 |
| T9-P1-03 | 错误 signature 的 latest.json | 检查更新 | **签名校验失败**类中文提示，不静默失败 |

### 3.3 P2次要用例（次要功能、异常场景）

| 编号 | 前置条件 | 步骤 | 预期结果 |
|------|----------|------|----------|
| T9-P2-01 | 拔网线 | 检查更新 | 网络错误类提示 |
| T9-P2-02 | Win7 + 文档要求 WebView2 | 安装与启动 | 记录实际结果（通过/阻塞原因）为兼容性结论 |

## 4. 专项测试方案

### 4.1 功能测试方案

覆盖第 3 节用例；第八版 US8-P0 用例抽样 **3** 条执行冒烟。

### 4.2 性能测试方案

- 检查更新在 **弱网** 下超时行为符合 **60s** 配置；UI 不永久卡死。

### 4.3 兼容性测试方案

- **Win10、Win8.1、Win7（扩展）** 矩阵；每环境记录 **WebView2** 与 **系统版本**。

### 4.4 安全性测试方案

- 验证 **HTTPS** 下检查更新；尝试 **篡改 signature** 应失败。
- 验证仓库 **无私钥** 文件提交。

### 4.5 可用性测试方案

- 浅色/深色主题下底部栏 **对比度可读**；刷新图标有 **aria-label**。

## 5. 自动化测试方案

### 5.1 自动化测试范围

- **scripts/version.mjs**：可用 Node 脚本做轻量集成测试（可选，第九版不强制）。

### 5.2 自动化测试工具选型

- 延续 **Vitest** 用于纯函数模块；更新插件依赖 **UI E2E** 第九版不强制。

### 5.3 自动化测试脚本设计规范

- 若有版本脚本测试，须 **临时目录** 写入再清理，不污染仓库。

## 6. 缺陷管理规范

### 6.1 缺陷分级标准

- **P0**：无法安装、无法启动、更新签名校验被绕过、版本号严重不一致。
- **P1**：检查更新偶发失败无重试提示、深色模式不可读。
- **P2**：Win7 文档未覆盖、文案笔误。

### 6.2 缺陷报告规范

须含 **环境、WebView2 版本、复现步骤、期望/实际、日志截图**。

### 6.3 缺陷闭环流程

修复 → 回归对应用例 → 测试负责人关闭。

## 7. 测试准入准出标准

### 7.1 测试准入标准

- 第九版构建产物在 **Win10** 上可手动安装；**P0** 用例脚本化评审通过。

### 7.2 测试准出标准

- **T9-P0-01～T9-P0-05** 全部通过；**T9-P1-01** 在 Win10 通过；第八版抽样冒烟通过；**无开放 P0/P1**。

### 7.3 上线阻断规则

- 任一 **P0** 未关闭；或 **私钥泄露**；或 **endpoints 非 HTTPS**（生产配置）。

## 8. 测试进度与里程碑

### 8.1 测试阶段划分

环境准备 → P0 全量 → P1 → 兼容性扩展 → 回归 → 准出评审。

### 8.2 测试里程碑节点

- **M1**：Win10 P0 完成；**M2**：更新链路与签名验证完成；**M3**：准出签署。

### 8.3 测试进度管控规则

每日记录阻塞项（网络、证书、虚拟机镜像）。
