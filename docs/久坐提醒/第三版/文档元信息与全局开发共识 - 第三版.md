## 3. 全局代码规范

### 3.1 目录结构规范

延续项目结构强制规范；第三版变更集中于 `HomePage` 调度副作用依赖策略、`QuietHoursSettingsPage` 展示结构及 `quietHours` 工具中的推迟算法、清洗与时段摘要能力，不新增顶层目录。

### 3.2 命名规则约束

与第二版一致；第三版新增纯函数命名建议：`formatQuietHourRangeLabel`（示意，用于免打扰折叠标题）。

### 3.3 代码编写通用规范

- 调度相关 `useEffect`（或等价订阅）依赖数组必须显式对齐「参与推迟算法与提醒总开关」的字段集合，禁止以整个配置对象为唯一依赖而导致非调度字段误触发重算；须附中文注释列出排除字段及原因。
- 提醒实际弹出时读取的文案、活动时长等展示向配置，须与「已排程的下次触发时刻」解耦：若收窄调度依赖，须保证触发回调读取**当前最新**配置，避免陈旧闭包。

## 4. 全局权限与安全规范

### 4.1 接口权限通用规则

第三版不新增后端命令；托盘仍仅同步三布尔（开机启动、提醒启用、提醒结束锁屏），与第二版一致。

### 4.2 数据安全规范

配置仍仅存前端本地；不向远端上报。

### 4.3 合规性要求

与第二版一致；用户清理存储导致配置丢失的风险说明不变。

## 5. 需求优先级定义

### 5.1 P0 核心需求清单

- 在提醒已启用且已排程下次触发的前提下，用户切换**开机自启**、**提醒结束后锁屏**、**开启随机文案**任一开关后，**主界面展示的「下次提醒时间」与经 `update_next_trigger` 同步的运行时镜像不得被重新计算为新的时刻**（除非用户同时修改了调度相关字段）。
- 调度相关字段变更（提醒总开关、规则间隔与规则启用、免打扰总开关、免打扰各段启用与起止时刻）仍须重算并同步下次触发；推迟算法在第三版扩展**跨午夜段**语义，同日段行为与第二版一致。

### 5.2 P1 重要需求清单

- 免打扰设置页中每个时段以可折叠面板展示；折叠态标题须包含 **HH:mm-HH:mm** 形式的时段摘要（与本地日内起止一致）；段级禁用时折叠标题可辅以「已关闭」等可读标识。
- 默认展开策略：进入免打扰页时各段默认展开，与第二版「全量字段可见」体验等价；折叠状态无需跨会话持久化。

### 5.3 P2 次要需求清单

- 时段摘要格式化函数具备单元测试覆盖（整点、补零、跨午夜摘要如 22:00-06:00）。
- 推迟算法对跨午夜晚间腿/清晨腿及左闭右开边界的单元测试覆盖。
