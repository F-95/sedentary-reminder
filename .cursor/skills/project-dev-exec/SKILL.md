# project-dev-exec

## 核心定位

本技能为Trae开发环节唯一执行技能，100%遵守开发环节所有强制规则，以用户输入的固定格式启动指令为唯一触发入口，以指令匹配路径下的锁定设计文档为唯一执行基准，严格按规则定义的智能体调用时机、执行顺序自动化流转，逐环节引导用户完成验收确认，最终实现从设计文档到可上线代码的全流程自动化闭环，全程禁止任何违规操作。

## 唯一触发条件

用户在独立会话中，输入完全符合固定格式的指令：**现在开始开XXX功能的第X版**

- 非此固定格式指令，一律不触发本技能，直接向用户反馈正确的指令格式
- 同一会话仅能触发一次本技能，禁止重复触发、多指令触发

## 执行步骤（严格按顺序执行，无用户确认绝对禁止跳步，每个环节明确【智能体调用时机】）

### 步骤1：指令解析与前置准入校验

1.  接收到合法启动指令后，自动完成以下操作：
    - 指令解析：自动提取「功能全称=XXX功能」「版本号=第X版」
    - 路径匹配：自动锁定设计文档归档路径为`/docs/XXX功能/第X版/`
    - 会话重命名：自动将会话名称修改为「XXX功能第X版开发任务」
2.  自动执行前置准入全量校验，校验不通过则立即终止流程，向用户明确反馈错误原因与修正方案，禁止进入后续环节：
    - 指令格式校验：确认指令完全符合固定格式，无错字、无简写、无格式偏差
    - 设计文档校验：读取对应路径下的7份全套设计文档，确认文档完整、无缺失、已锁定
    - 会话环境校验：确认当前会话为全新独立会话，无其他功能上下文混杂
    - 项目环境校验：确认项目已完成初始化，开发环境、工具链配置完整
3.  自动识别开发场景：根据设计文档内容，自动识别是「新功能开发」还是「老功能迭代开发」，匹配对应的执行流程与智能体调用规则。
4.  向用户输出校验结果、开发场景识别结果、完整的执行流程、智能体调用顺序、各环节验收标准，等待用户确认「同意开启本次开发任务」。

---

### 步骤2：架构适配性评审环节

【智能体调用时机】

- 触发前置条件：步骤1校验全部通过、用户明确确认「同意开启本次开发任务」
- 调用角色：系统架构专家
- 执行职责：严格遵循对应开发场景的专项规则，完成设计文档开发适配性评审、影响范围评估、架构约束输出
- 必须输出物：《开发适配性评审报告》《架构执行约束标准》，迭代场景需额外输出《迭代影响评估报告》《回滚方案模板》

1.  自动@系统架构专家，传递以下信息：
    - 本次开发的功能全称、版本号、设计文档路径、识别的开发场景
    - 全套锁定的设计文档、项目环境信息
    - 要求严格遵循开发规则，完成对应场景的架构评审与约束输出
2.  系统架构专家输出完成后，自动校验输出物是否符合规则要求，不符合则重新生成；校验通过后，向用户完整展示评审报告与架构约束，引导用户确认。
3.  闭环标准：用户明确输出「评审通过，同意进入开发环节」，未通过则按用户要求修改后重新评审，禁止进入下一环节。
4.  锁定本环节所有输出物，同步到会话上下文，作为后续所有环节的执行依据。

---

### 步骤3：后端开发环节

【智能体调用时机】

- 触发前置条件：步骤2架构评审通过、用户明确确认进入开发环节
- 调用角色：Rust后端专家
- 执行职责：严格遵循设计文档与架构约束，完成对应场景的后端代码开发、校验、自测
- 必须输出物：《后端开发完成报告》《单元测试报告》《后端接口契约》，迭代场景需额外输出《代码变更对比表》

1.  自动@Rust后端专家，传递以下信息：
    - 本次开发的功能全称、版本号、开发场景、设计文档路径
    - 全套锁定设计文档、步骤2锁定的架构约束与评审报告
    - 要求严格遵循开发规则，100%匹配《后端详细设计（Rust）》完成开发，通过所有强制校验，禁止修改与迭代无关的历史代码
2.  Rust后端专家输出完成后，自动校验是否符合规则要求：①是否100%匹配设计文档；②是否通过所有强制校验；③是否符合代码规范，不符合则重新生成；校验通过后，自动@系统架构专家做架构合规评审，输出评审意见。
3.  评审通过后，向用户完整展示后端开发交付物、校验结果、评审报告，引导用户验收。
4.  闭环标准：用户明确输出「本环节验收通过，可进入下一环节」，未通过则按用户要求修改后重新提交，禁止进入下一环节。
5.  锁定本环节所有输出物，同步到会话上下文，作为下一环节的执行依据。

- 必须输出物：《前端开发完成报告》《前端接口请求封装文档》，迭代场景需额外输出《代码变更对比表》

5.  锁定本环节所有输出物，同步到会话上下文，作为下一环节的执行依据。

- 必须输出物：《测试报告》《缺陷清单》《测试通过报告》，迭代场景需额外输出《回归测试报告》

2.  测试专家输出《缺陷清单》后，自动同步给对应开发专家，开发专家完成修复后，自动执行回归测试，直至所有P0-P1级缺陷全部闭环，输出《测试通过报告》。

### 步骤8：全量交付物归档与闭环环节

【智能体调用时机】

- 触发前置条件：步骤7最终需求验收通过
- 调用角色：系统架构专家
- 执行职责：完成交付物归档校验、合规性校验、回滚方案验证（迭代场景）
- 必须输出物：《归档校验报告》《全流程合规性校验报告》，迭代场景需额外输出《回滚方案验证报告》

1.  自动@系统架构专家，传递以下信息：
    - 本次开发的功能全称、版本号、开发场景、设计文档路径
    - 开发全流程所有锁定的输出物、代码仓库信息、最终验收报告
    - 要求严格遵循开发产物归档规则，完成归档校验、合规性校验，迭代场景需额外完成回滚方案验证
2.  系统架构专家完成校验后，自动执行归档操作，将所有交付物写入对应版本的设计文档目录`/docs/XXX功能/第X版/`，向用户反馈每个交付物的存储路径、写入结果。
3.  向用户输出完整的任务闭环报告，包含：功能名称、版本号、开发场景、全流程执行情况、各环节验收结果、交付物归档路径、代码仓库地址、分支/标签信息、合规性校验结果、后续操作建议。
4.  明确告知用户：本次开发任务已完全闭环，如需迭代或新增功能，需开启全新独立会话，输入对应固定格式启动指令。

## 强制输出规范

1.  所有代码必须100%匹配对应版本锁定设计文档的要求，零偏差、无遗漏、无私自变更。
2.  所有代码必须符合项目强制规范，通过所有前置校验，零告警、零错误、可直接编译运行。
3.  每个环节必须输出对应的标准化报告，结构清晰、数据准确，可直接归档使用，禁止模糊表述。
4.  所有输出物必须明确完整的相对路径，可直接通过Trae文件系统工具写入对应位置，无需用户手动调整。
5.  后续环节的内容必须严格基于前面已确认、已锁定的环节内容，禁止出现前后冲突、需求偏离的问题。
6.  全程禁止任何与设计文档要求不符的操作，禁止输出任何无依据、无规范的内容。

## 绝对禁忌规则

1.  禁止非固定格式指令触发本技能，禁止在同一会话中多次触发本技能。
2.  禁止在设计文档未锁定、前置校验未通过的情况下，进入后续环节、调用任何智能体。
3.  禁止在未完成当前环节用户确认、内容未锁定的情况下，跳步进入下一环节。
4.  禁止未按规定时机、前置条件调用智能体，禁止越权调用、无依据调用智能体。
5.  禁止开发内容与锁定设计文档的要求不符，私自变更、偏离设计文档定义的内容。
6.  禁止未通过强制校验的代码进入下一环节，禁止隐瞒代码中的缺陷、风险。
7.  禁止未向用户展示完整的交付物、验收报告，就直接写入文件系统、完成归档。
8.  禁止覆盖、删除历史版本的归档内容，禁止修改已锁定的环节输出物。
9.  禁止违反开发环节任何强制规则与绝对禁忌红线。

## 执行完成后必须输出

1.  开发任务完成的明确确认信息、全流程验收结果。
2.  完整的项目交付物清单，包含所有文档、代码、报告的存储路径。
3.  代码仓库地址、分支/标签信息、后续构建与部署命令、迭代场景的回滚操作命令。
4.  全流程合规性校验报告、归档校验报告。
5.  后续迭代、运维、优化的操作建议与注意事项。
6.  常见问题排查指引。
