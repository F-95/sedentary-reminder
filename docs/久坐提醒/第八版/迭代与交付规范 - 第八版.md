# 迭代与交付规范-第八版

> **【已锁定】** 锁定日期：2026-05-12。

## 1. 迭代计划

### 1.1 版本迭代目标

发布第八版：枢纽久坐手动推进、统计 kind 扩展、双序列堆叠与四类合计、情绪简报；后端命令集不变。

### 1.2 迭代里程碑节点

文档锁定 → 前端与类型实现 → 工具单测 → 构建验证 → 测试准出 → 打包发布。

### 1.3 任务拆分与排期

`global.d.ts` → `statsBuckets` / `statsEmotionalBrief` → `HomePage` / `ReminderSettingsPage` → `StatisticsPage` / `StatsBriefCard` → 联调验收。

## 2. 代码管理规范

### 2.1 分支管理规则

建议分支名 `久坐提醒-第八版` 或与仓库约定一致（如「久坐提醒功能-第八版」按组织规范）。

### 2.2 代码提交规范

提交信息包含：第八版 + 模块 + 简述；关联设计文档章节（如「第八版·枢纽手动推进·需求 US8-P0-01」）。

### 2.3 代码合并与评审规则

`npm run build`、`vitest`、`cargo test`（如涉及）通过再合并；统计合计与 JSONL 抽样对齐评审。

## 3. 构建与打包规范

### 3.1 构建环境要求

与《文档元信息-第八版》技术栈一致。

### 3.2 构建流程规则

`npm ci` → `npm run build` → `cargo build` → `tauri build`（与仓库脚本一致）。

### 3.3 打包产物规范

Windows NSIS/MSI；应用版本号以仓库 `package.json` / `Cargo.toml` / `tauri.conf.json` 为准；Git 标签遵循仓库发布惯例。

### 3.4 补丁/插件交付适配规则

第八版不新增补丁包；无 capability 变更。

## 4. 发布与部署规范

### 4.1 发布流程

Release notes 说明：枢纽可记录活动/跳过、统计图语义变更、简报功能；提醒用户旧 JSONL 自动兼容新 kind。

### 4.2 部署环境要求

用户本机安装；无服务端。

### 4.3 灰度发布规则

与第七版相同策略；可选内测构建。

## 5. 回滚规范

### 5.1 回滚触发条件

严重调度缺陷或统计数据大面积错误。

### 5.2 回滚执行步骤

用户安装上一稳定版本；JSONL 保留历史事件，旧版客户端忽略未知 kind 时不应崩溃（若旧版仅识别部分 kind，需在产品说明中提示「回滚后新 kind 行仍存在但不展示」——以实际旧代码为准，发布说明中披露）。

### 5.3 回滚验证标准

第七版功能恢复；配置可读；应用可启动。
