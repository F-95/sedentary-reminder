### 2.2 依赖版本管理规范

- 前端锁文件：`package-lock.json` 必须随依赖变更同步提交。
- 后端锁文件：`Cargo.lock` 必须随依赖变更同步提交。
- 任一依赖主版本升级必须触发新版本设计文档（文档版本号递增），并在《迭代与交付规范》中登记构建与兼容性验证要求。

### 2.3 跨平台兼容要求

- **构建目标**：本仓库 CI 与 README 以 Windows 为主要交付形态；macOS、Linux 可作为扩展构建目标，但部分能力存在平台差异。
- **开机自启**：当前实现仅在 Windows（HKCU Run 注册表）可用；非 Windows 平台调用返回明确错误字符串。
- **锁屏**：当前实现仅在 Windows 通过 `LockWorkStation` 间接调用；非 Windows 返回不支持错误。
- **企业强控（Enterprise Layer）**：提醒全屏强制模式在 Windows 下包含额外窗口层级加固逻辑；其他平台按 Tauri 窗口 API 行为降级。

## 3. 全局代码规范

### 3.1 目录结构规范

严格遵循项目根目录 `.cursor/rules/project-structure.mdc` 定义：`src/`（React）、`src-tauri/src/commands/`（Tauri 命令）、`src-tauri/src/core/`（核心业务状态）、`docs/`（设计文档按「功能全称 / 版本号」归档）、`patches/` 与 `plugins/`（扩展运行时目录，编译产物不入库）。

### 3.2 命名规则约束

- 目录：全小写 + 短横线。
- Rust 模块与文件：全小写 + 下划线。
- React 页面与组件文件：大驼峰（如 `HomePage.tsx`）。
- 工具与类型文件：小驼峰或与现有仓库保持一致。

### 3.3 代码编写通用规范

- 所有新增代码必须附带中文注释；涉及平台差异、并发锁、窗口生命周期的地方必须写明边界条件与安全假设。
- 禁止随意修改 `src-tauri/src/extensions/` 核心扩展实现；补丁与插件加载遵循扩展目录约定。
- Ant Design 全局主题仅在 `src/App.tsx` 的 `ConfigProvider` 配置；页面级组件禁止深度覆盖 AntD DOM 结构。

## 4. 全局权限与安全规范

### 4.1 接口权限通用规则

- 前端通过 Tauri `invoke` 调用已注册的命令；未注册命令不得从前端调用。
- 托盘菜单通过后端事件向前端同步布尔字段切换；后端不直接读取浏览器 `localStorage`。

### 4.2 数据安全规范

- 提醒配置（间隔、文案、开关等）默认仅存于前端 `localStorage`（键名由前端常量定义）；用户卸载应用或清理浏览器数据会导致配置丢失。
- 开机自启写入当前用户注册表键值，不涉及管理员权限假设。

### 4.3 合规性要求

- 通知能力依赖系统通知权限与用户授权；授权拒绝时必须静默降级不得阻断核心线程。
- 远程铃声 URL 若配置或使用在线资源，需遵守对应站点使用条款（第一版默认示例地址来自 Pixabay CDN，网络不可用时应降级处理）。

## 5. 需求优先级定义

### 5.1 P0 核心需求清单

- 可配置提醒间隔并在启用状态下按间隔触发提醒流程。
- 提醒呈现包含全屏沉浸式界面与活动倒计时流程。
- 用户可启用或停用提醒总开关。

### 5.2 P1 重要需求清单

- 系统托盘展示并与提醒启用状态、下次提醒文案摘要联动。
- 主窗口关闭行为：非强制提醒态下可选择最小化到托盘或退出（可记忆偏好）。
- Windows 开机自启配置。
- Windows 活动结束后锁屏可选开关。

### 5.3 P2 次要需求清单

- 文案随机展示与自定义多条文案。
- 临近触发前约一分钟的系统通知提醒。
- 补丁列表与插件列表占位命令（扩展系统预留）。

## 6. 文档适用范围与边界说明

### 6.1 本文档适用范围

适用于「久坐提醒」桌面应用第一版（当前仓库已实现的提醒核心、托盘、窗口模式切换、锁屏与自启）相关的需求分析、架构设计、前后端详细设计、测试验收与交付归档。
