# 测试与验收方案-第十版

> **【归档基线】** 与实现版本 **v0.1.10** 对齐；归档日期：2026-05-14。

## 1. 测试概述

### 1.1 测试范围

覆盖第十版增量：**全屏右键屏蔽**、**底部用户须知**、**解锁视为记录活动**（含 Win/mac 事件与前端门闩）、**调度快照**（指纹、首轮 merge、禁用路径）、**主窗 800 与提醒结束恢复**、**久坐子页布局**；回归第九版 **版本展示与检查更新**、第八版枢纽统计 **不受破坏**。

### 1.2 测试目标

证明功能符合《需求规格说明书-第十版》中 **US10-P0 / P1** 可量化条目；Release 流水线 **CHANGELOG 小节存在**。

### 1.3 参考依据

《需求规格说明书-第十版》《系统总体设计-第十版》《后端详细设计（Rust）-第十版》《前端详细设计（React）-第十版》《迭代与交付规范-第十版》。

## 2. 测试环境与工具

### 2.1 测试环境配置要求

| 环境 | 要求 |
|------|------|
| Win10 x64 | 已安装 WebView2；本地可写应用数据目录 |
| Win11 x64 | 同上做主测 |
| macOS | 最低版本以 CI/实机声明为准；需可锁屏解锁 |
| 构建 | `npm ci`、`npm run build`、`cargo build` 可过 |

### 2.2 测试工具清单

- 应用内置 **枢纽展示**、**统计页**（验证事件计数）。
- 系统 **锁屏/解锁**（Win+L / mac 菜单）。
- 文本编辑器查看 **`%AppData%` 下应用目录** 中 `scheduler_snapshot.json`（路径以 `identifier` 为准）。

### 2.3 测试数据准备规范

- **基线配置**：久坐开启、间隔例如 **60** 分钟；补水可开可关（覆盖两条链路）。
- **快照准备**：运行 ≥1 分钟使生成快照后 **正常退出** 再启动以测恢复。

## 4. 专项测试方案

### 4.1 功能测试方案

- 按 §3 用例矩阵执行；**每条 P0 必须通过** 方可进入准出。

### 4.2 性能测试方案

- 连续 **10 次** 保存快照操作，主观无卡顿；CPU 占用无异常飙升（非仪器化门槛）。

### 4.3 兼容性测试方案

- **Win10 + 旧 WebView2**：验证全屏右键屏蔽仍有效（与渲染内核无强依赖）。
- **macOS**：验证解锁事件在 **真实锁屏** 下可触发（至少 **3/3** 次成功样本）。

### 4.4 安全性测试方案

- 快照 JSON 手工注入超长 `fingerprint`：应用应拒绝使用或截断策略与实现一致且无 **RCE** 面（反序列化固定结构体）。

### 4.5 可用性测试方案

- 5 分钟内新用户能否 **找到** 用户须知与解锁开关（可选抽样 **≥3** 人，主观记录）。

## 5. 自动化测试方案

### 5.1 自动化测试范围

- **`quietHours`**：`buildSchedulerFingerprint` **稳定性**（同配置同串、排序规则不变）；`parseReminderConfigV2` 对 **`logActivityOnSessionUnlockEnabled`** 默认值与解析。

### 5.2 自动化测试工具选型

- **Vitest**（与仓库现状一致）。

### 5.3 自动化测试脚本设计规范

- 新增指纹用例须 **断言** `quietHours` 导出函数输出长度 **> 0** 且对同一 `ReminderConfig` **严格相等**。
- **禁止** 在 Vitest 中启动真实 Tauri 子进程作为硬性门槛（可选 E2E 另立项）。

## 6. 缺陷管理规范

### 6.1 缺陷分级标准

| 级别 | 定义（第十版语境） |
|------|---------------------|
| P0 | 全屏仍可弹出菜单；解锁记活动误触发导致统计不可信；快照导致 **早于 now** 触发 |
| P1 | Tooltip 缺失；mac 解锁偶发不触发且无文档说明 |
| P2 | 文案错别字 |

### 6.2 缺陷报告规范

须含：**复现步骤、期望、实际、环境、是否全屏、开关状态、是否附快照文件**。

### 6.3 缺陷闭环流程

发现 → 定位 → 修复 → 回归对应 TC 编号 → 关闭。
