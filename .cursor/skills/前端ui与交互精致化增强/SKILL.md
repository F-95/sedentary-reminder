# 前端UI与交互精致化增强 Skill
## 核心目标
1.  强制优先调用项目已安装的UI框架/组件库/样式框架，杜绝脱离现有生态原生硬写样式，从根源解决UI框架闲置问题
2.  输出符合现代前端设计标准的高质感页面，统一视觉规范，消除样式混乱、排版粗糙问题
3.  全链路增强页面交互体验，补齐用户操作反馈、动画过渡、无障碍访问等核心交互能力
4.  保证生成的页面全终端响应式适配，代码结构清晰可维护，符合前端工程化规范

## 适用场景
- 生成全新的前端页面/业务组件时
- 重构现有页面的UI样式与交互逻辑时
- 优化页面视觉质感、修复样式错乱问题时
- 补齐页面交互反馈、动画过渡、响应式适配能力时
- 要求页面必须使用项目已集成的UI框架开发时

## 前置执行步骤（必须严格按顺序执行）
1.  **项目依赖扫描**：首先读取项目根目录的 package.json 文件，100%识别已安装的UI相关依赖，包括但不限于：
    - 组件库：Ant Design、Element Plus、Arco Design、Naive UI、TDesign、Shadcn UI等
    - CSS框架：Tailwind CSS、UnoCSS、Windi CSS等
    - 样式方案：Sass/Less、Styled Components、CSS Modules等
2.  **框架优先级锁定**：将识别到的UI框架设为本次开发的唯一优先样式方案，禁止使用未在项目中安装的第三方UI依赖，禁止脱离已有的UI框架原生编写重复样式
3.  **规范匹配**：根据识别到的UI框架，自动匹配其官方设计规范与最佳实践，组件使用必须符合官方API标准，禁止私自修改组件核心底层样式

## 一、UI框架强制使用规范（最高优先级，违反视为无效输出）
1.  页面90%以上的基础UI元素，必须使用已识别UI框架的原生组件实现，包括但不限于：按钮、表单、表格、弹窗、卡片、导航、分页、提示框等
2.  仅当UI框架原生组件无法满足特殊业务需求时，才可基于框架的扩展能力进行自定义封装，禁止完全重写同功能组件
3.  必须完整使用UI框架的全局主题配置能力，统一页面主题色、圆角、字号、间距等设计token，禁止出现与主题规范冲突的零散样式
4.  针对不同UI框架的专属规则：
    - 若为组件库（AntD/Element Plus等）：优先使用组件props配置样式/状态，仅通过框架提供的覆盖类名做少量定制，禁止全局样式污染
    - 若为原子化CSS框架（Tailwind CSS等）：100%使用框架工具类实现样式，禁止新建CSS文件写自定义样式，仅允许在tailwind.config.js中扩展主题配置
    - 若为CSS Modules/Scoped CSS：样式必须作用域隔离，禁止使用/deep/深度选择器修改UI框架组件的全局样式

## 二、视觉设计强制规范（杜绝粗糙页面）
1.  **色彩系统规范**
    - 主色/辅助色/成功/警告/错误色必须使用UI框架预设色值，禁止自定义十六进制色值；无预设时必须建立统一的色彩变量，禁止页面内出现零散色值
    - 文本层级严格遵循：主标题-副标题-正文-辅助文字-置灰文字的对比度标准，正文文本与背景对比度不低于4.5:1，符合WCAG无障碍标准
    - 禁止使用高饱和刺眼配色、渐变滥用、多色混杂，保证页面主色不超过3种，辅助色不超过5种

2.  **排版与间距规范**
    - 字号必须使用UI框架预设的阶梯体系，无预设时使用固定字号阶梯（12px/14px/16px/20px/24px/32px），禁止出现奇数/非阶梯字号
    - 行高规范：标题行高1.2-1.3，正文行高1.5-1.6，禁止行高过小导致文字挤压、行高过大导致排版松散
    - 间距必须使用8px栅格系统，所有内外边距必须为8px的倍数（4px仅用于极小内边距场景），禁止出现1px/3px/5px/7px等零散边距
    - 页面内容必须有最大宽度限制与水平居中，禁止内容贴边浏览器窗口，桌面端左右留白不小于24px，移动端不小于16px

3.  **元素质感规范**
    - 卡片/弹窗/面板必须使用合理的圆角、阴影层级，禁止直角生硬元素；圆角规范：按钮圆角4-8px，卡片圆角8-12px，弹窗圆角12-16px
    - 阴影层级严格区分：悬浮元素（下拉框/弹窗）> 可点击卡片 > 静态卡片 > 页面底色，禁止阴影过重、模糊半径过大导致的脏污感
    - 可交互元素与静态元素必须有明确视觉区分，按钮/输入框/选择器等必须有清晰的边框、内边距、视觉焦点，禁止无边框无背景的弱交互元素

## 三、交互体验增强规范（核心能力补齐）
1.  **基础交互反馈（必须100%覆盖）**
    - 所有可点击元素（按钮、链接、卡片、图标）必须提供hover、active、focus三种状态的视觉反馈，禁止点击无任何状态变化
    - 按钮点击后必须有加载状态，禁止重复点击；表单提交、接口请求过程中必须有全局/局部加载动画，禁止页面无响应假死
    - 表单操作必须有实时校验与错误提示，校验信息必须紧跟对应表单项，禁止仅在顶部/底部统一提示；成功/失败操作必须有全局提示/弹窗反馈

2.  **动画与过渡规范**
    - 所有元素的显隐、展开收起、悬浮切换，必须添加平滑过渡动画，过渡时长规范：微交互200ms，元素显隐300ms，页面切换400ms
    - 动画缓动函数规范：入场动画使用ease-out，出场动画使用ease-in，通用交互使用ease-in-out，禁止生硬的无过渡切换
    - 动画仅用于提升交互体验，禁止滥用全屏动画、长时间动画影响操作效率，保证动画不阻塞页面渲染

3.  **进阶交互优化**
    - 列表/表格必须支持排序、筛选、分页，大数据场景必须添加虚拟滚动优化
    - 弹窗/抽屉关闭前必须有二次确认（有表单内容时），禁止误触导致内容丢失
    - 长页面必须提供回到顶部按钮，导航栏滚动时必须有吸顶效果
    - 键盘操作支持：Tab键可正常聚焦所有可交互元素，Enter键可触发按钮点击，Esc键可关闭弹窗/抽屉

## 四、响应式与适配规范
1.  页面必须采用流式布局+弹性布局，禁止使用固定宽度写死页面，保证从320px移动端到1920px+桌面端的全尺寸适配
2.  断点规范必须统一：移动端<768px，平板768px-1200px，桌面端>1200px，禁止零散断点
3.  移动端适配要求：按钮最小点击区域不小于44px*44px，表单元素字体不小于16px（避免iOS自动缩放），横向布局在移动端自动转为纵向堆叠
4.  必须适配不同屏幕缩放比例，保证100%-200%页面缩放时，布局不错乱、内容不溢出

## 五、代码实现规范
1.  样式与业务逻辑完全分离，禁止在JSX/模板中写大量行内样式，仅允许动态绑定样式使用行内写法
2.  组件化拆分：页面必须按功能拆分为独立组件，单个组件代码行数不超过500行，禁止单文件全量堆砌代码
3.  禁止使用!important强制覆盖样式，仅在极端特殊场景可使用，且必须添加注释说明原因
4.  生成的代码必须可直接运行，无语法错误、无依赖缺失、无样式冲突，UI框架组件的引入路径、API调用必须完全正确

## 六、校验与兜底规则
1.  代码生成完成后，必须反向校验：是否100%使用了项目已有的UI框架，是否存在未使用框架原生组件的情况
2.  若未识别到项目中的任何UI框架，才可使用HTML+原生CSS实现，且必须遵循本Skill的视觉与交互规范，同时必须告知用户未检测到UI框架的情况
3.  若用户有额外的视觉风格要求，必须在本规范的基础上叠加，不得与本规范的强制规则冲突
