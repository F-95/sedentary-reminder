# 迭代与交付规范-第七版

> **【已锁定】** 锁定日期：2026-05-11。

## 1. 迭代计划

### 1.1 版本迭代目标

发布第七版：主窗口标题（健康搭子）、作者随笔子页与枢纽入口；后端零变更。

### 1.2 迭代里程碑节点

文档锁定 → 前端与配置实现 → 构建验证 → 测试准出 → 打包发布。

### 1.3 任务拆分与排期

`tauri.conf.json` + `index.html` → `AuthorBlurbPage` → `HomePage`/`ReminderSettingsPage` 联调 → 验收。

## 2. 代码管理规范

### 2.1 分支管理规则

建议分支名 `久坐提醒-第七版` 或与仓库约定一致。

### 2.2 代码提交规范

提交信息包含：第七版 + 模块 + 简述（如 `feat(v7): author blurb page`）。

### 2.3 代码合并与评审规则

`npm run build` 通过再合并；文案与需求逐字核对。

## 3. 构建与打包规范

### 3.1 构建环境要求

与《文档元信息-第七版》技术栈一致。

### 3.2 构建流程规则

`npm ci` → `npm run build` → `cargo build` → `tauri build`。

### 3.3 打包产物规范

Windows NSIS/MSI；**应用版本号**仍以 `package.json` / `Cargo.toml` / `tauri.conf.json` 仓库当前值为准（第七版为文档迭代号，可与 semver 独立）；Git 标签遵循仓库发布惯例。

### 3.4 补丁/插件交付适配规则

第七版不新增补丁包；无 capability 变更。

## 4. 发布与部署规范

### 4.1 发布流程

更新 `CHANGELOG.md`（若维护）、Release notes 中说明标题与关于作者入口；GitHub Release 附件安装包。

### 4.2 部署环境要求

用户本机安装；无服务端。

### 4.3 灰度发布规则

可选内测构建；与第六版相同策略。

## 5. 回滚规范

### 5.1 回滚触发条件

严重崩溃或文案合规问题需紧急下线。

### 5.2 回滚执行步骤

用户安装上一稳定版本；第七版无新数据文件，无需额外清理。

### 5.3 回滚验证标准

第六版功能恢复；配置与统计可读。

## 6. 交付物清单

### 6.1 设计文档清单

`docs/久坐提醒/第七版/` 下七份 Markdown（本文档集）。

### 6.2 代码产物清单

`index.html`、`tauri.conf.json`（标题字段）、`AuthorBlurbPage.tsx`、`HomePage.tsx`、`ReminderSettingsPage.tsx` 差异。

### 6.3 验收交付物清单

测试用例执行记录、构建日志、已知问题列表（若有）。

## 7. 验收标准

### 7.1 功能验收标准

与《需求规格说明书-第七版》P0 一致。

### 7.2 质量验收标准

无 P0/P1 未修复缺陷；`npm run build` 通过。

### 7.3 交付验收流程

测试确认 → 发布负责人签发。

## 8. 线上运维规范

### 8.1 线上问题处理流程

Issue 收集 → 复现 → 补丁版本或下版合并。

### 8.2 日志与监控规范

### 8.3 迭代优化规则
