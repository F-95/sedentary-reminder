# 迭代与交付规范-第一版

## 1. 迭代计划

### 1.1 版本迭代目标

固化久坐提醒桌面应用第一版核心功能交付基线，并为后续「免打扰时段」第二版迭代提供比对锚点。

### 1.2 迭代里程碑节点

| 里程碑 | 说明 |
|--------|------|
| M1 设计冻结 | 七份设计文档第一版归档 |
| M2 构建可用 | Windows 调试构建通过 |
| M3 验证完成 | 测试方案执行完毕 |

### 1.3 任务拆分与排期

由项目负责人基于人力资源拆分：设计归档、开发同步（已在主干）、测试验证、Release 资产上传。

## 2. 代码管理规范

### 2.1 分支管理规则

- 主干：`main`（或仓库默认分支）。
- 功能迭代第二版建议使用独立分支 `久坐提醒-第二版`（与全局规则对齐）。

### 2.2 代码提交规范

提交信息包含：功能模块关键词、变更摘要；关联设计章节编号（如有）。

### 2.3 代码合并与评审规则

合并前至少一名评审者通过；高风险窗口逻辑变更需附加截图或录屏。

## 3. 构建与打包规范

### 3.1 构建环境要求

见《文档元信息与全局开发共识-第一版》固定工具链版本。

### 3.2 构建流程规则

- 前端执行类型检查与生产构建流水线（具体步骤由仓库脚本定义）。
- Rust 侧 release 构建需关闭调试断言一致性行为以贴近交付。

### 3.3 打包产物规范

- Windows：安装包格式遵循仓库 CI 配置（NSIS 与 MSI）。
- 版本号：`package.json` 与 `Cargo.toml` 对齐；应用内 `get_app_info` 返回值不一致问题需在后续迭代修复并列入变更说明。

### 3.4 补丁/插件交付适配规则

扩展包不入库存储二进制；交付清单包含 manifest 与 schema。

## 4. 发布与部署规范

### 4.1 发布流程

创建版本标签 → CI 构建草稿 Release → 人工审核 Release 说明 → 正式发布。

### 4.2 部署环境要求

终端用户环境：Windows 10+；可选安装权限：当前用户。

### 4.3 灰度发布规则

第一版以 GitHub Releases 为主要渠道；企业侧可采用内部分发前置小范围试用。

## 5. 回滚规范

### 5.1 回滚触发条件

发现 P0 级崩溃或错误锁屏严重影响可用性。

### 5.2 回滚执行步骤

下架对应 Release 资产公告 → 引导用户安装上一稳定标签构建 → 保留缺陷记录。

### 5.3 回滚验证标准

上一版本关键用例重新执行通过。

## 6. 交付物清单

### 6.1 设计文档清单

《文档元信息与全局开发共识-第一版》《需求规格说明书-第一版》《系统总体设计-第一版》《后端详细设计（Rust）-第一版》《前端详细设计（React）-第一版》《测试与验收方案-第一版》《迭代与交付规范-第一版》（本文档）。

### 6.2 代码产物清单

仓库 `src/`、`src-tauri/` CI 构建配置与脚本。

### 6.3 验收交付物清单

测试记录、已知问题列表、Release 二进制与校验说明。

## 7. 验收标准

### 7.1 功能验收标准

满足《需求规格说明书-第一版》P0、P1 用户故事量化标准。

### 7.2 质量验收标准

无打开状态的 P0；P1 缺陷_closed；构建产物可安装启动。

### 7.3 交付验收流程

测试负责人出具通过结论 → 产品确认范围 → 架构复核文档归档齐全。

## 8. 线上运维规范

### 8.1 线上问题处理流程

Issues 收集 → 分级 → 修复计划 → 补丁版本或第二版迭代。

### 8.2 日志与监控规范

第一版无强制远程监控；依赖用户反馈与本地复现。

### 8.3 迭代优化规则

改进项进入下一版本需求与设计文档流程。
