## 2. 全局技术栈规范

### 2.1 固定技术栈与版本号约束

与《文档元信息与全局开发共识-第一版》完全一致，禁止在未立项依赖升级审批的情况下改动下列版本：

- Tauri `2.0.0`
- React `18.2.0` / Vite `5.0.10` / TypeScript `5.2.2`
- Ant Design `5.12.0`
- @tauri-apps/api `2.0.0`、通知插件 `2.0.0`
- Rust Edition `2021`，serde `1.0.193`，tokio `1.35.0`

### 2.2 依赖版本管理规范

同第一版；若免打扰特性引入新前端依赖（不推荐），必须在共识文档版本升级段落登记精确版本号。

### 2.3 跨平台兼容要求

免打扰判定基于前端本地时区（Local Timezone）与日历日界线；夏令时切换日边界场景需在测试方案覆盖。

## 3. 全局代码规范

### 3.1 目录结构规范

延续项目结构强制规范；免打扰相关 UI 增量置于 `src/pages/ReminderSettingsPage.tsx` 或拆分的同层级页面文件（若后续拆分须保持命名大驼峰）。

### 3.2 命名规则约束

新增类型命名示例：`QuietHourRange`（示意）；字段采用 camelCase 与 JSON 持久化一致。

### 3.3 代码编写通用规范

- 调度推迟算法必须附带中文注释说明终止条件（最大迭代次数防止配置异常死循环）。
- 迁移函数必须注明从 `reminder-config-v1` 到 `reminder-config-v2` 的字段默认值策略。

## 4. 全局权限与安全规范

### 4.1 接口权限通用规则

第二版不新增后端命令；免打扰配置不出现在托盘同步参数中（托盘仍仅同步三布尔）。

### 4.2 数据安全规范

免打扰配置随提醒配置写入前端本地持久化；不向远端上报。

### 4.3 合规性要求

用户撤销存储权限（浏览器清理）将导致配置丢失，与第一版一致。

## 5. 需求优先级定义

### 5.1 P0 核心需求清单

- 支持启用总开关后配置多个免打扰时段；时段内不触发提醒。
- 命中免打扰时，将「下一次触发时刻」推迟到离开所有重叠免打扰区间之后，再叠加完整提醒间隔。

### 5.2 P1 重要需求清单

- 单个时段可独立启用/禁用；总数上限（建议最多 20 段）超出时给出校验提示。
- 提醒会话进行中进入免打扰：**不中断**当前会话；会话结束后重新计算下一次触发。

### 5.3 P2 次要需求清单

- 重叠时段允许共存，由算法合并推迟效果。
- 本地时间变更时的边界提示（测试覆盖）。

## 6. 文档适用范围与边界说明

### 6.1 本文档适用范围

久坐提醒第二版迭代设计与实现基准。

### 6.2 本文档约束边界

- 不包含跨午夜免打扰（结束时刻必须严格大于开始时刻且同日完成）。
- 不包含按星期与工作日的日历维度（第二版明确不做）。
- 不包含后端持久化免打扰规则。
